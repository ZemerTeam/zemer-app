# 04 - The UI

Both surfaces observe `LatestReleasesViewModel.releases` and share per-item behaviour through
`latestreleases/` - the `Artist • <relative date>` subtitle, `isNowPlaying`, the `openOrPlay` tap,
the long-press album menu and `ReleaseBadges` - so they cannot drift.

## The Home shelf (`ui/screens/HomeScreen.kt`)

- Its own `hiltViewModel()` (independent of `HomeViewModel`), capped with
  `latestReleases.take(12)`. A non-empty feed counts toward `hasRemoteHomeContent`.
- Inside the MUSIC tab, after Music Status and directly above Zemer Playlists, emitted only when the
  capped list is non-empty: a `NavigationTitle` (`latest_releases_title`; tap → the `latest_releases`
  route) and a `HorizontalMultiBrowseCarousel` (`latest_releases_list`; `preferredItemWidth = 180.dp`,
  `heroCarouselFlingBehavior` for one item per swipe) of `LatestReleaseCarouselItem`.
- **`LatestReleaseCarouselItem`** is the shared `CarouselHeroFrame` (cover-crop art, D-pad focus ring
  following the item morph) + `HeroTitleOverlay` (title, subtitle, `ReleaseBadges` forced white on the
  scrim). Long-press → `ytItemMenu(release.toAlbumItem(), …)`. A single shows the centred
  `OverlayPlayButton`; an album shows the corner `AlbumPlayButton`, which runs `playAlbum` (local
  album rows if stored, else one Zemer `album` fetch; a 404/empty/failed fetch opens the album page -
  never InnerTube). The now-playing treatment is withheld while the tapped single is still preparing
  (`rememberIsPreparing`), and the hero pops once as it becomes active (`rememberActivationPopScale`).

## The See-all screen (`ui/screens/LatestReleasesScreen.kt`, route `latest_releases`)

The **full** list in a `LazyColumn` (`LocalPlayerAwareWindowInsets` padding):

- First item: an All / Albums / Songs `ChipsRow` over `LatestReleaseFilter` (`rememberSaveable`);
  `applyFilter` keeps `isPlayableSingle()` releases for SONGS and the rest for ALBUMS, in feed order.
- Rows are `LatestReleaseCard` (a `YouTubeListItem` via its `subtitleOverride` +
  `centeredPlayButton` params in `ui/component/Items.kt`; long-press → `YouTubeAlbumMenu`). The date
  label is memoized per `browseId`.
- A shuffle `HideOnScrollFAB`, visible when the filtered list is non-empty:
  `visibleReleases.shufflePlay(...)` queues the `sampleTracks()` of **what the filter shows** (albums
  included, any release with a `sampleVideoId`), shuffled.
- `BackTopAppBar` with `AppBarTitle(stringResource(R.string.latest_releases))`. An empty feed is just
  an empty list.

## Tap behaviour (`latestreleases/LatestReleasePlayback.kt`)

```kotlin
fun LatestRelease.openOrPlay(navController, playerConnection) {
    val single = playableSingle()
    if (single != null) playerConnection.playQueue(ZemerRadioQueue.song(single, playerConnection.service, PlaySource.NEW))
    else navController.navigate("album/$browseId")
}
```

- `isPlayableSingle()` = `trackCount == 1 && sampleVideoId` present. It drives **both** the tap and the
  centred play button, so the icon never promises playback the tap won't deliver
  (`LatestReleasePlaybackTest` pins that they agree).
- A single plays seed-first song radio (`ZemerRadioQueue.song`); anything else - including an older
  feed with no `trackCount` - opens the album.
- `isNowPlaying(mediaMetadata)`: a single matches on the **track id** (`mediaMetadata.id ==
  sampleVideoId`; its metadata carries no album, so an album-id check would never light); an album
  matches on `mediaMetadata.album.id == browseId`.

The only string is `latest_releases` in `res/values/metrolist_strings.xml`; the date labels come from
`DateUtils`.
