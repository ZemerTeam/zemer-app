# 05 — The UI

Two surfaces render the feed, both observing `LatestReleasesViewModel.releases`: the Home shelf
and the "See all" screen. The Home shelf renders each release as a
`latestreleases/LatestReleaseCarouselItem` (a Material 3 Expressive carousel hero); the See-all
list renders each as `LatestReleaseCard` (`latestreleases/LatestReleaseCard.kt`), which is now
**list-only** (a `YouTubeListItem`; there is no `asGrid` param). Both share the per-item behaviour —
the album mapping, the `Artist • <relative date>` subtitle, the single's centred play button, the
now-playing state (`isNowPlaying`), the tap (`openOrPlay`), the long-press album menu and the
library badges (`ReleaseBadges`) — so the two surfaces cannot drift.

## The Home shelf (`ui/screens/HomeScreen.kt`)

### Wiring

- The feed ViewModel is obtained independently of `HomeViewModel`:
  ```kotlin
  val latestReleasesViewModel: LatestReleasesViewModel = hiltViewModel()
  val latestReleases by latestReleasesViewModel.releases.collectAsState()
  ```
- The shelf is **capped at 12** items:
  ```kotlin
  val latestReleasesCapped = remember(latestReleases) { latestReleases.take(12) }
  ```
- A non-empty feed counts as remote Home content for the shimmer/empty logic
  (`hasRemoteHomeContent`), so the feed alone is enough to show Home as populated.

### Placement and render

The shelf is on the **Music** content tab, after the Music Status row and **directly above Zemer
Playlists** (`zemer_playlists_title` follows it). It is two lazy items — a header and a
`HorizontalMultiBrowseCarousel`:

```kotlin
latestReleasesCapped.takeIf { it.isNotEmpty() }?.let { releases ->
    item(key = "latest_releases_title", contentType = "header") {
        NavigationTitle(
            title = stringResource(R.string.latest_releases),
            onClick = { navController.navigate("latest_releases") },   // "See all"
            modifier = Modifier.animateItem()
        )
    }
    item(key = "latest_releases_list", contentType = "grid") {
        val latestCarouselState = rememberCarouselState { releases.size }
        HorizontalMultiBrowseCarousel(
            state = latestCarouselState,
            preferredItemWidth = 180.dp,
            itemSpacing = 8.dp,
            flingBehavior = heroCarouselFlingBehavior(latestCarouselState),   // one item per swipe
            contentPadding = WindowInsets.systemBars.only(WindowInsetsSides.Horizontal).asPaddingValues(),
            modifier = Modifier.padding(vertical = 12.dp).height(180.dp).animateItem(),
        ) { index ->
            LatestReleaseCarouselItem(
                release = releases[index],
                navController = navController,
                playerConnection = playerConnection,
                mediaMetadata = mediaMetadata,
                isPlaying = isPlaying,
                coroutineScope = scope,
            )
        }
    }
}
```

Key points:

- **Header tap = "See all":** the `NavigationTitle.onClick` navigates to the `latest_releases`
  route.
- **Visibility:** `takeIf { it.isNotEmpty() }` — when the filtered feed is empty, the header and
  carousel are not emitted at all.
- **Layout:** each hero is the shared `CarouselHeroFrame` (cover-crop artwork, `maskClip`/`maskBorder`
  D-pad focus ring following the carousel morph) with a `HeroTitleOverlay` (title + subtitle + the
  library badges, forced white on the dark scrim). `heroCarouselFlingBehavior`
  (`ui/component/CarouselHeroFrame.kt`) advances one item per swipe.
- **Active state:** `isActive = release.isNowPlaying(mediaMetadata)`
  (`latestreleases/LatestReleasePlayback.kt`). A single plays as a videoId with no album bound, so
  it matches on the **track id** (`mediaMetadata?.id == sampleVideoId`); an album is active when a
  track from it is playing (`mediaMetadata?.album?.id == browseId`). The now-playing treatment is
  withheld while the tapped single is still preparing, and the hero pops once as it becomes active
  (`rememberActivationPopScale`).
- **Subtitle:** `joinByBullet(release.artistName, release.relativeDateLabel())` shows
  `Artist • <relative date>`. `joinByBullet` drops null/empty parts, so an unparseable date
  degrades to just the artist.
- **Tap behaviour:** `release.openOrPlay(...)` — a single (`trackCount == 1`) plays immediately
  with autoplay radio, anything else opens `album/<id>` (see "Tap behaviour" below). Long-press ->
  the album menu (`ytItemMenu(release.toAlbumItem(), …)`). A single shows the centred
  `OverlayPlayButton`; an album shows the corner `AlbumPlayButton`, which plays the album directly
  (`playAlbum`).

## The "See all" screen (`ui/screens/LatestReleasesScreen.kt`)

A `@Composable fun LatestReleasesScreen(navController, scrollBehavior, viewModel = hiltViewModel())`
showing the **full** feed (no `take(12)`) as a vertical list:

- The screen body is a `Box(Modifier.fillMaxSize())` holding the list and the FAB.
- A `LazyColumn` (with a `rememberLazyListState()`, needed by the FAB) padded with
  `LocalPlayerAwareWindowInsets`.
- An **All / Albums / Songs** `ChipsRow` as the first list item (it scrolls with the list), over
  `LatestReleaseFilter` (`latestreleases/LatestReleaseFilter.kt`): `applyFilter` keeps singles
  (`isPlayableSingle()`) for SONGS and everything else for ALBUMS, preserving feed order. The
  selection is `rememberSaveable`, and the rows render `visibleReleases = releases.applyFilter(filter)`.
- Each row is a `LatestReleaseCard` (a `YouTubeListItem`) — the subtitle, the single's centred play
  button, the now-playing state, the `openOrPlay` tap and the `YouTubeAlbumMenu` long-press are all
  the shared card's, not re-implemented here.
- A **shuffle FAB** via the shared `HideOnScrollFAB` (`ui/component/HideOnScrollFAB.kt`),
  `icon = R.drawable.shuffle`, `visible = visibleReleases.isNotEmpty()`. Its `onClick` calls
  `visibleReleases.shufflePlay(playerConnection, getString(R.string.latest_releases))` — it shuffles
  what the current filter shows.
- The shared `BackTopAppBar` titled via `AppBarTitle(stringResource(R.string.latest_releases))`.
- When the feed is empty/unavailable the list is simply empty (and the FAB hides) — nothing is forced.

### Route (`ui/screens/NavigationBuilder.kt`)

```kotlin
composable("latest_releases") {
    LatestReleasesScreen(navController, scrollBehavior)
}
```

Both `hiltViewModel()` call sites resolve to a `LatestReleasesViewModel`; the underlying
`LatestReleasesStore` is a process-wide `object`, so the cached feed and once-per-launch refresh
are shared across the Home shelf and the See-all screen.

## Tap behaviour — `openOrPlay` (`latestreleases/LatestReleasePlayback.kt`)

Both surfaces route a card tap through one shared extension so the behaviour can't drift:

```kotlin
fun LatestRelease.openOrPlay(navController, playerConnection) {
    val single = playableSingle()                                   // non-null only for a 1-track single
    if (single != null) playerConnection.playQueue(ZemerRadioQueue.song(single, playerConnection.service, PlaySource.NEW))
    else navController.navigate("album/$browseId")
}
```

- `playableSingle()` (`:22`) is the **pure, Android-free** core of the decision: it returns the
  track's `MediaMetadata` only when `trackCount == 1` and a `sampleVideoId` exists, and `null`
  otherwise (a real album, or an older cached feed with no track count). It is unit-tested without
  a player or Android runtime (doc 06).
- A **single** plays immediately via `ZemerRadioQueue.song` (seed-first: the track is the preload
  AND heads the queue, `/radio?kind=song` fill follows) — the same queue every single-song tap uses,
  so music continues after the track.
- Anything else **opens the album page** (`:44`) — the prior behaviour, and the safe fallback
  whenever `trackCount` is absent.
- Long-press is unchanged on both surfaces: `YouTubeAlbumMenu`.

**Visual affordance.** A release the tap will actually play (`isPlayableSingle()` — `trackCount == 1`
with a videoId) shows the song-style **centred** play button on its artwork (the same
`OverlayPlayButton` the Keep Listening song cards use), on both the Home hero and the See-all row.
An album keeps the **corner** `AlbumPlayButton` on the Home hero and no button on the list row.
The list row passes this via the `centeredPlayButton` flag (the carousel hero picks its button from the
same `isPlayableSingle()`), so the icon never promises playback the tap won't deliver (the flag and `openOrPlay` read the same predicate — pinned by the test in doc 06).

## Card params: `subtitleOverride` + `centeredPlayButton` (`ui/component/Items.kt`)

Both grid- and list-item composables gained two optional params. `LatestReleaseCard` (list-only
now) sets them on its `YouTubeListItem`; the Home carousel hero renders its own subtitle/button via
`HeroTitleOverlay` + `OverlayPlayButton`/`AlbumPlayButton` (consistent with `docs/ui/standards.md`
section 1, reuse before building):

- **`subtitleOverride: String? = null`** — replaces the computed subtitle (here, to put
  `Artist • <relative date>` on the card). When null the card computes its normal subtitle (for an
  `AlbumItem`: `artists` and `year`). `YouTubeListItem` param `:839`, used at `:871`;
  `YouTubeGridItem` param `:943`, used at `:958`.
- **`centeredPlayButton: Boolean = false`** — when true the artwork shows the centred
  `OverlayPlayButton` (the song-card style) instead of an album's corner `AlbumPlayButton` (grid) /
  no button (list). `YouTubeGridItem` swaps the button on the flag (`:989-996`); `YouTubeListItem`
  overlays it on the row thumbnail (`:879-893`). Default false, so every other caller is unchanged.
