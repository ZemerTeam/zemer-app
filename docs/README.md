# Zemer repository documentation

This documentation records facts visible in tracked repository files and avoids product claims that are not backed by source files, Gradle configuration, Android resources, generated Room schemas, or Kotlin declarations. Runtime data from YouTube, Firebase, Android services, or user preferences is documented only as code paths and stored fields.

Two kinds of documents live here:

- **Generated by `docs/generate.py`** (never hand-edit; regenerated on every push to `main` by `.github/workflows/docs-regenerate.yml`): `reference/kotlin-files.md`, `reference/non-kotlin-files.md`, `reference/resource-index.md`, `build-release.md`, the inventory tail of `repository-map.md` (from its `### Counts` heading down), and every region between a `<!-- generated:NAME -->` / `<!-- /generated:NAME -->` marker pair in `app/README.md`, `app/database.md`, `app/playback.md`, `app/preferences-sync-auth.md`, `app/viewmodels.md`, `ui/README.md` and `innertube/README.md` (the file, package, DAO, schema, preference-key, ViewModel, route and consumer inventory tables). To change one of those tables, change the generator (`REGION_DOCS` in `docs/generate.py`), not the doc.
- **Hand-maintained**: everything else - the top of `repository-map.md`, the prose around the generated regions in the `app/`, `innertube/` and `ui/` docs (including the `InnerTube` / `YouTube` method-description tables in `innertube/README.md` and the contributor study map in `app/README.md`), and the per-feature docsets, which are prose that cites the source files.

## Ground rules used while documenting

- Facts are derived from tracked files and local source inspection only.
- Generated build directories and Gradle caches are not treated as product source.
- Inventories use scripts over tracked files; they intentionally report declarations and metadata instead of inventing behavior.
- If a tracked path is a gitlink or cannot be text-decoded, the docs record that fact rather than content.
