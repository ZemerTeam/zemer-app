# Music Status - third-party status platforms

The app's **"Music Status"** Home row and full-screen story viewer draw WhatsApp/Stories-style
"status" content from **third-party platforms**. This folder documents each platform's public API in
enough detail to build and maintain a client against it. These are **hand-authored reference docs**
(not generated by `docs/generate.py`) - keep them current when a platform's shape changes.

> These are **external services we do not control.** Everything here was reverse-engineered from the
> platforms' own public web apps and verified against the live endpoints on the date noted in each file.
> Treat every endpoint as best-effort and fail-soft: the feature is designed to simply hide when a feed
> is empty or unreachable (see `docs/...` / the `statuses/` package), and any of these endpoints can change
> or tighten without notice.

## Platforms

| Platform | Doc | Backend | Status in the app |
|----------|-----|---------|-------------------|
| **JewishStatus** (jewishstatus.com) | [jewishstatus-api.md](jewishstatus-api.md) | Supabase (PostgREST) + Cloudflare R2 | **Integrated** - powers Music Status today (`com.jtech.zemer.statuses`). |
| **YidStatus** (yidstatus.com) | [yidstatus-api.md](yidstatus-api.md) | Supabase (custom domain `api.yidstatus.com`) + Supabase Storage | **Evaluated 2026-08-02, feed confirmed reachable.** Not yet integrated. |

## At a glance

| | JewishStatus | YidStatus |
|---|---|---|
| Creator list | `POST /rpc/browse_creators_sorted` per category (3 categories) | `POST /rpc/avatar_strip` **or** the `influencers` array in the feed |
| Status read | `GET /public_posts?creator_id=eq....` (per creator, paginated) | `POST /functions/v1/feed` (**one global call**, all creators + statuses) |
| Auth | publishable anon key (`apikey` header), client-safe | anon JWT (`apikey` header), client-safe |
| **Access gate** | none - plain public PostgREST | **`/feed` requires `Origin: https://yidstatus.com`** (server-side check); the RPCs are open |
| Media | Cloudflare R2, paths relative -> prefixed client-side | Supabase Storage, **full URLs returned in the response** |
| Shape | one creator -> many posts | global feed -> statuses carry `influencer_id` |
| Payload size | small, per creator | **large** - ~19 MB for `days:7` (313 creators / 13.4k statuses); use a small `days` or `since` |

## Field mapping (both -> the app's model)

Both platforms map cleanly onto the app's existing `StatusPost` / `StatusCreator` shape:

| App field | JewishStatus | YidStatus |
|-----------|--------------|-----------|
| creator id | `id` | `id` (= status `influencer_id`) |
| creator name | `display_name` | `name` |
| creator avatar | `avatar_path` (relative) | `avatar_url` (full) |
| status id | `id` | `id` |
| status kind | `kind` (`video`/`image`/`text`) | `type` (`video`/`image`/`text`/**`audio`**) |
| media | `media_path` (relative) | `media_url` (full) |
| thumbnail | `thumb_path` (relative, videos) | `poster_url` (full, videos; null for images) |
| caption | `caption` | `caption` |
| text body | `text_body` | `caption` (text statuses put the body here) |
| text bg color | `text_bg_color` | `background_color` |
| duration | `duration_seconds` | `duration_seconds` |
| timestamp (UTC) | `posted_at` | `timestamp` |

Notable YidStatus-only concepts to handle if integrated: an **`audio`** status type (no analog in
JewishStatus), an **`is_ad`** flag + `storyAds`/`placements` (must be filtered out for kosher content),
and rich link-preview fields (`link_title`/`link_image_url`/...).

## Integration caveats (read before wiring YidStatus in)

- **Origin gate.** `/functions/v1/feed` returns `403 {"error":"Forbidden"}` unless the request carries
  `Origin: https://yidstatus.com`. A native client (OkHttp / `HttpURLConnection`) can set that header -
  it is not CORS-enforced off-browser - and the call then succeeds. It is trivially spoofable, so it will
  work today, but the platform could tighten it (allowlist change, Turnstile, per-IP limits) at any time.
  Design fail-soft.
- **One big payload.** The feed is global and returns everything for the window in a single response.
  Prefer a **small `days`** (e.g. 1) and/or the incremental **`since`** cursor; never fetch a wide window
  on the hot path.
- **Ads & unlisted.** Filter `is_ad` statuses, `paused`/`unlisted`/`review_hidden` influencers, and the
  `storyAds`/`placements` arrays. None of that is kosher-relevant content.
- **Client-safe keys only.** The anon/publishable keys in these docs are the same ones the platforms ship
  in their public web bundles (RLS-scoped, read-only). They are **not** secrets. Do **not** confuse them
  with a Supabase *service-role* key (never present here).

See each platform's file for the full endpoint list, request/response shapes, field tables, and gotchas.
